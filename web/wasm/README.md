Detection ABI and integration

The real kernel is detect-wasm.c, built by sh wasm/build-detect.sh with clang/lld. No libc, imports, backend requests, or runtime dependencies. The TypeScript wrapper exports await init(bytesOrURL), setImage(gray Uint8Array,w,h), setRefs(rotations Uint8Array[1024]), classifyBatch(quads Float32Array[N*8], optional Float32Array[N*5] OR count N). Returns [ok,rotation,score,margin,votes] per patch. It also exports detectorBackend. Default asset URL resolves relative to the bundled script; an explicit '/detect-wasm.wasm' URL is recommended when bundling.

After await init(), call setRefs(new Uint8Array(makeRefs(ref).flat())), setImage(gray,w,h), then pass hooks { classifyBatch: (q,n) => classifyBatch(q,n) } into runDetection. This matches src/detect/detect.ts batchClassify hooks. The wrapper chunks at 4096, grows bounded WASM memory and copies only image once, refs once and batches afterward. State is per worker; no concurrent images in one module instance.

The native exports set_refs(ptr) and classify_batch(grayPtr,w,h,quadPtr,count,outPtr) operate on exported linear memory. __heap_base marks available host scratch space. All pixel warp, homography fitting, Pearson correlation and quadrant voting happen inside WASM. SIMD f64x2 lanes hold template rotations rather than pixels so addition order matches the JS reference exactly, with contraction disabled. Sampling is rounded to Float32 before Pearson as in the reference. The Float32 ABI necessarily rounds input corners and output scores; compare both engines using the same corners and Float32 scores for strict threshold consistency.

Validation Nov 1 on actual hill screenshot: 7401 perspective voxel patches including its accepted faces plus singular/out-of-bounds cases. 4384 valid patches. All validity/rotation/quadrant-vote/acceptance decisions identical. Maximum score/margin difference 2.96e-8 (Float32 output). WASM 74.9 ms vs JS 922.0 ms, 12.31x faster, Node24 V8 on this sandbox, same inputs. This is kernel timing, not a claim for total feature detection speed.

Run npx tsx wasm/test-detect.ts from web, or Node24 wasm/test-detect.ts. The fixtures are regression inputs, not browser auto-detection output.
